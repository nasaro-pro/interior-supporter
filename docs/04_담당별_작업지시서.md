## 1. 작업 방법 — AI 를 쓰든 안 쓰든 같다

1. 00 헌법 5.3 대로 **스타터 ZIP 을 내 폴더에 풀고** `npm install` → Supabase 연결 → `npm run db:test`(110개 통과) → `npm run check:ownership -- --owner <나>`(변경 0). 이미 기준서로 작업 중이면 00 헌법 5.11 전환 절차부터.
2. 읽는 순서: **00 헌법**(특히 2·3·4·5·7장) → 이 문서의 **내 장**(남과의 연결 포함) → 01 문서 4장(내 REQ)·3장(정책)·7장(결정 대장) → 02 문서(내 화면, 5·6장) → 03 문서 2~5장·9장(대응표).
3. 남의 기능은 STUB(00 헌법 5.7) → 내 기능 TASK 를 **Must 부터 하나씩**.
4. TASK 마다: 구현 → `npm run format && npm run check` → 해당 검증 ID 직접 확인 → 진행 기록 1·6번 갱신 → `check:ownership` 위반 0 확인.
5. S3(Must 완료)에 중간 제출, 끝나면 00 헌법 11.3 체크 → 진행 기록 8번에 검사 결과 → `npm run submit -- --owner <나>` → 폴더를 ZIP 으로 압축해 통합 책임자에게 전달.

### 1.1 AI(GPT·Claude 등)를 쓰는 경우 — AI 작업 문서 하나를 통째로 넣는다

| 담당 | AI 에 넣을 파일 (이것 하나면 충분) |
|---|---|
| A 박예원 | `ai/AI_작업문서_A_박예원.md` |
| B 류영걸 | `ai/AI_작업문서_B_류영걸.md` |
| C 이재서 | `ai/AI_작업문서_C_이재서.md` |

- AI 작업 문서는 00 헌법 전문·01~04 문서 중 내 부분·계약 코드·내 영역 DB 스키마·내 화면·내 요구사항·검증표·남과의 연결을 **한 파일에 모은 것**이다. 별도 지시문(프롬프트)을 쓰지 않는다. 대화를 시작할 때 이 파일을 첨부(또는 프로젝트 지식에 등록)하고 "TASK-105 진행" 처럼 TASK 번호만 말한다.
- 팀 기준서 2종(평가서·데이터아키텍처)은 함께 넣지 않는다 — 내용은 이미 반영됐고, 논리 이름이 코드에 섞인다.
- 문서가 바뀌면 통합 책임자가 `python scripts/build-ai-docs.py` 로 다시 만들어 스타터 개정으로 배포한다(직접 고치지 않는다).

### 1.2 AI 없이 직접 만드는 경우
같은 문서·같은 규격을 그대로 따른다. 특히 03 문서 5.1 의 Server Action 표준 예시를 복사해서 시작하고, 00 헌법 7.1 이름 규칙 표를 옆에 두고 작업한다.
