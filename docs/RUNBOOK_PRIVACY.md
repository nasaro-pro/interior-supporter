# 정보주체 권리 런북

파일럿 업체에서도 조회·삭제 요청이 들어온다. 처리 기한은 법률 자문 후 확정하고, 그때까지는 **접수 당일 담당자가 스크립트를 돌릴 수 있게** 이 문서를 쓴다.

담당: 플랫폼 운영자. 업체 총관리자가 직접 스크립트를 실행하지 않는다.

개인정보 원문(연락처·주소·이메일)은 감사 로그 `before`/`after`에 남기지 않는다.

## 1. 조회·내보내기

계정 UUID(`users.id`)를 확인한 뒤:

```bash
cd web
pnpm privacy:export -- <userId>
```

표준출력 JSON. 포함: 계정(식별값), 멤버십·프로젝트 접근(id만), 작성한 요청·댓글·일지, 확정 검증 여부(코드 평문 없음).

프로젝트 사진·도안 파일은 **업체 자산**이므로 이 내보내기에 바이너리를 넣지 않는다. 요청자가 현장 사진 사본을 원하면 해당 업체 총관리자가 포털 공개분을 전달한다.

## 2. 계정 파기(익명화)

프로젝트·업체 데이터는 지우지 않는다. 계정 PII만 제거하고 로그인을 막는다.

```bash
cd web
pnpm privacy:erase -- <userId> --confirm
```

하는 일:

- `users.is_active = false`, 이름·이메일 토큰화, `phone` 비움
- 세션 삭제
- 해당 계정의 `project_access` 회수
- 해당 계정의 활성 멤버십 비활성화
- 감사: `member_deactivate` (개인정보 원문 없음)

되돌릴 수 없다. 실행 전 export JSON을 운영 보관함에 남긴다.

## 3. 업체 해지 후 콘텐츠 파기

`ARCHITECTURE.md` 15.3 — 이용 기간 + 해지 후 30일. 별도 배치(`retention`)가 감사 로그만 지운다. **프로젝트 파일 일괄 삭제는 이 스크립트에 넣지 않았다.** 해지가 확정되면 플랫폼 운영자가 업체 상태를 `suspended`로 두고, 30일 뒤 스토리지 접두어 `{companyId}/`와 DB 행 삭제를 수동 점검한다.

## 4. 처리 기록

요청 접수일, 완료일, 실행한 스크립트와 `userId`만 내부 티켓에 남긴다. 이메일 원문을 감사 로그에 복사하지 않는다.
